Prezentáció Vázlat: ArtisticEye Vizsgaremek

1. Diakép: Címoldal és Bemutatkozás
* Cím: ArtisticEye – Modern, interaktív képmegosztó és közösségi platform alkotóknak.
* Készítők: Fodor Zsombor Dezső és Gerencsér Ákos
* Célkitűzés: Egy Pinterest-stílusú vizuális galéria ötvözése a modern közösségi média funkcióival (valós idejű chat, követési rendszer, értesítések).

2. Diakép: Alkalmazott Technológiák és Architektúra
* Infrastruktúra: Teljesen konténerizált környezet. A docker-compose.yml segítségével egyetlen paranccsal (npm start) indul a Frontend, a Backend, a MySQL adatbázis és a Docusaurus dokumentáció.
  - Kiemelendő DevOps megoldás: Az adatbázis konténer induláskor automatikusan inicializálja a sémát és az alapértelmezett adatokat a `/docker-entrypoint-initdb.d/` könyvtárba csatolt SQL fájlból.
* Dokumentáció: A projekt dedikált, Docusaurus alapú dokumentációs oldallal rendelkezik, ami garantálja a szoftver jövőbeli karbantarthatóságát.
* Frontend: React.js (Vite), React Router DOM a navigációhoz, tiszta CSS3 (változókkal és animációkkal).
* Backend: Node.js, Express.js REST API.
* Adatbázis: MySQL 8.0, szigorú relációs modellel.

3. Diakép: Adatbázis Tervezés és Biztonság
* Struktúra: Normalizált adattáblák (users, posts, categories, follows, messages, likes).
* Adatintegritás: ON DELETE CASCADE szabályok alkalmazása (pl. ha egy felhasználó törlődik, a posztjai és kommentjei is).
* Biztonság (Backend): 
  - JSON Web Token (JWT) alapú hitelesítés az API végpontokon (authenticateToken middleware).
  - Jelszavak egyirányú titkosítása Bcrypt.js segítségével.
  - Teljes védelem SQL Injection ellen paraméterezett lekérdezésekkel (Prepared Statements).

4. Diakép: Frontend Fejlesztés – UI/UX és Fontosabb Importok
* Architektúra: Jól strukturált mapparendszer (components/, pages/, hooks/, contexts/, services/). Kliensoldali állapotkezelés beépített React Hook-okkal és Context API-val.
* Dizájn: Glassmorphism (üveghatás, backdrop-filter), Neon akcentusok, és reszponzív "Masonry" (téglafal) rácsszerkezet.
* Kiemelt Frontend Könyvtárak (Importok):
  - react-toastify: Felhasználói visszajelzések (siker/hiba popupok) elegáns megjelenítése.
  - clsx: Feltételes CSS osztályok dinamikus és tiszta kezelése a komponensekben.
  - react-icons: Vizuális elemek, ikonok biztosítása.
  - axios: API hívások lebonyolítása egy dedikált service rétegen keresztül.

5. Diakép: Backend Fejlesztés – Képfeldolgozás és Valós idejű funkciók
* Intelligens Képfeldolgozás (A rendszer egyik legfőbb erőssége):
  - A multer könyvtár fogadja a fájlokat memóriaszinten (buffer).
  - A sharp könyvtár azonnal átméretezi, tömöríti és egységesen .jpeg formátumra alakítja azokat, mielőtt a fájlrendszerbe kerülnének. (Eredmény: Drasztikusan alacsonyabb hálózati sávszélesség és gyorsabb betöltés).
* Architekturális döntés (BLOB vs. Fájlrendszer): 
  - Kezdetben az adatbázisban tároltuk a képeket (LONGBLOB), de teljesítmény-optimalizálási okokból írtunk egy migrációs szkriptet (migrate_images.js), ami áthelyezte a képeket a szerver fájlrendszerébe, így a MySQL már csak az URL-t (image_url) tárolja. Ez hatalmas terhet vett le az adatbázis-szerverről.
* Valós idejű kommunikáció:
  - Socket.IO alapú WebSocket kapcsolat az azonnali értesítésekhez és a privát chathez.
  - Szerveroldali memória tároló (Map) használata az átmeneti adatokhoz (pl. "Gépelés jelzése"), hogy ne terheljük feleslegesen az adatbázist másodpercenkénti írás/olvasás kérésekkel.

6. Diakép: Adminisztráció, Moderáció és Üzleti logika
* Tartalommoderáció: Beépített "Report" rendszer, ahol a felhasználók jelenthetik a nem megfelelő posztokat, amit az adminisztrátorok a Dashboardon kezelnek.
* Visszajelzések: Dedikált modul a hibajelentésekre és javaslatokra (feedbacks).
* Marketing eszközök: Beépített hírlevél feliratkozó és küldő rendszer (Newsletter) az aktív közösség fenntartásához.

7. Diakép: Minőségbiztosítás és Tesztelés
* Egység- és Integrációs tesztek: Vitest + React Testing Library (komponensek és állapotváltozások tesztelése).
* E2E és Vizuális Regressziós Tesztek: Cypress (teljes felhasználói folyamatok és a felület elcsúszásának figyelése).
* Automatizált UI Tesztek (Selenium WebDriver): 
  - Dedikált szkriptek (pl. admin_tests.js, header_search_tests.js) automatizált Chrome böngészővel tesztelik az admin bejelentkezést, táblázatok megjelenését és a keresőmező debounce funkcióját.
* Manuális Tesztelés: Lighthouse audit, ahol az alkalmazás "Kiváló" (90+) pontszámot ért el teljesítmény és hozzáférhetőség terén.

8. Diakép: Fejlesztés során felmerült lehetséges hibák és megoldásaik
1. A Kereső API túlterhelése (Frontend probléma): 
   - Hiba: Minden leütésnél azonnal elindult egy hálózati kérés a Backend felé.
   - Megoldás: "Debounce" mechanizmus bevezetése, így csak a gépelés befejezése után indul a kérés.
2. Gépelés jelzésének villogása lassú hálózaton:
   - Hiba: A typingIndicator zavaróan villogott, ha akadozott a net.
   - Megoldás: Debounce és késleltetett állapotfrissítés a kliens oldalon. A backenden pedig a typingStatus.get(key) egy 2000ms-es ablakot vizsgál.
3. Vizuális torzulás a Masonry galériában:
   - Hiba: Extrém képernyőméreteken felborult a grid elrendezés.
   - Megoldás: Vizuális regressziós tesztek bevezetése Cypress-szel, és a CSS Media Query-k finomhangolása.
4. Aszinkron állapotkezelési anomáliák (React):
   - Hiba: A state-ek nem frissültek időben, "Race condition" lépett fel.
   - Megoldás: A useEffect hook-ok és a függőségi tömbök (dependency arrays) szigorú felülvizsgálata, melyet a Vitest egységtesztek segítettek felderíteni.

9. Diakép: Zárás és Továbbfejlesztési lehetőségek
* Projekt összegzése: Egy skálázható, robusztus és felhasználóbarát platform készült el.
* Jövőbeli tervek: Pl. jelszó nélküli OAuth (Google/GitHub) bejelentkezés, AI alapú képcímkézés, vagy a mikroszerviz architektúra felé való elmozdulás.
* Kérdések és válaszok.

Tanács a vizsgához:
Amikor az importokról beszélsz, emeld ki, hogy nem mindent írtatok nulláról, de a választott eszközöket (pl. sharp, multer, socket.io) tudatosan, a teljesítmény optimalizálása céljából integráltátok. A tesztelési részhez érve nagyon jó pont, ha élőben futtatsz egy Selenium vagy Cypress tesztet, mivel a vizsgáztatók szeretik látni az automatizációt működés közben!
